Data issues to raise with Samar

  1. GA4 keeps event data for only two months on this property. Admin → Data settings → Data retention is set to "2 months". This analysis fits inside it today, but per-person queries will lose Oct 11 around Dec 11 and keep losing a day each day, so it cannot be re-run on this period later. Switching to 14 months is one click and free (I did not change it).
  2. Return milestones go missing for some accounts. 7 sign-ups fired user_return_2d, but only 5 of them fired user_return_1d before it; 4 sign-up days show more people at a higher N. The likeliest cause is a return on another device or browser, which GA4 treats as a different person. Ask Samar whether the GA4 user_id is set on every event once someone is logged in, so GA4 can join devices. Until then, every return number here is a floor.
  3. onboarding_entered does not behave as the sheet describes. The sheet says it fires once per user, but summed by day it counts 439 people against 428 distinct people over the period, so it fired on more than one day for some of them (11 extra), and 43 of 123 sign-ups have no onboarding_entered before their account_created in the period (they may have entered before Oct 11, used "I have an account", or the event did not fire). Worth asking Samar which.
  4. Developer traffic lands in the production property. localhost and Vercel preview deploys report to it. This report keeps only app.thoughtsaver.com; a GA4 data filter or a separate dev property would keep it clean everywhere.
  5. The full history may already exist in BigQuery. The property has a BigQuery export (Google Cloud project 200310840257) that is not subject to the two-month limit. I don't have access; with read access the per-person data would be kept permanently.

How this was measured

Only the events in Samar's sheet: onboarding_entered, account_created, onboarding_completed, user_return_1d to user_return_10d. A sign-up cohort = people who fired account_created on app.thoughtsaver.com on that day. They count for an event if they fired it at any point after their account_created (for returns: on at least N separate later days, per the sheet). Built with GA4 closed funnels, which follow each person, one funnel per day and event. Independent check: one funnel per event over the whole period gave exactly the same totals as the per-day funnels (all matched). Confidence intervals: Wilson 95%. Returns counted through Nov 10; data pulled 2026-11-11 09:57. Code: reports/thoughtsaver_retention_cohorts_2026-11-11_src/; tests: tests/test_thoughtsaver_retention_cohorts.py.
