Get Coaching button on the tools via GTM

Assessment and tested snippet. 2026-10-19 02:41pm, link decision added 2026-10-21 10:05am

Verdict: do it through GTM, with the snippet in gtm/coaching_fab_tools.html. A Custom HTML tag in GTM-WGXZSLV, firing on All Pages where Page Hostname equals programs.clearerthinking.org, shows the same button on every tool page without touching the programs or the Wix site. Injected into live tool pages exactly the way GTM injects Custom HTML, it produced no console errors, overlapped no program control on desktop or phone, stayed in place across program pages and reached /coaching 40 ms after a click.

Two limits GTM cannot remove: visitors with an ad blocker never load GTM, so they never see the button, and the personality-test landing only loads GTM once the test starts. If either matters after a few weeks of data, move the snippet into the team’s static site (option B below); the GTM version costs nothing to retire.

3. What could break a program, and what the snippet does about it

RiskHandling
Shared container: tag could fire on www and double the buttonTrigger condition Page Hostname equals programs.clearerthinking.org, plus a hostname guard and an “already present” check inside the snippet.
A tool page framed inside another site would show two buttonsRuns only in the top-level window (window.self === window.top).
personality-test.html rebuilds <body> when the test startsGTM loads after the rebuild there anyway; a MutationObserver re-attaches the button if any page ever removes it.
Phones: GuidedTrack pins the header to the top and, for programs declaring *navigation, a 48 px bar to the bottomWhen a bottom bar exists on a narrow screen the button lifts 48 px. None of the staged CT programs use *navigation, so this is a safety net.
GuidedTrack’s native payment panel is fixed to the bottomButton hides while #payment-ui-container exists. CT’s paid flows redirect to Stripe Checkout, so this should never trigger.
Button covering the last button of a page88 px bottom padding on the program’s .main while the button is present (GT’s own 60 px of bottom space already kept them apart; the padding adds margin for full-width answer buttons).
Stacking orderz-index 1040: above every GuidedTrack fixed element (max 1000), below Bootstrap modals (1050). The Wix embed uses 2147483000, which would also cover modals.
Bootstrap and main.css restyling the linkSame !important colour and text-decoration rules as the Wix embed; the button sits outside .program_container .main, so the site’s link rules do not reach it.
A script error breaking a programWhole snippet wrapped in try/catch, vanilla JS, no jQuery or GuidedTrack dependency; 5.7 KB (GTM limit 100 KB).
GTM’s link-click interceptionThe container’s Just Links trigger has “Wait for Tags” (2 s) on for both hosts, so GTM cancels every link click and re-navigates once its tags fire. In the click-through test the request for /coaching left 40 ms after the click, so no practical delay. The setting is still on (probed on /coaching too), but a click on a nav anchor there did not reload the page in this test, so the Oct 1 anchor bug did not reproduce; not investigated further.
AttributionNo utm parameters (the team’s convention for tool links: utm on internal links overwrites the session’s real source). The tested version linked with ?src=tools_fab; on 2026-10-21 Igor switched the link to the Wix utm set (utm_source=tools&utm_medium=banner&utm_campaign=tools_floating_button), so a /coaching visit from the button is attributed in GA4 to tools / banner and starts a new session. Clicks are already measurable from day one as cta_click with link_url containing src=tools_fab; the snippet also pushes coaching_fab_click for a dedicated GA4 event tag if wanted.

5. Setting it up in GTM (about 15 minutes)

  1. Tag: Tags > New > Custom HTML, name Get Coaching FAB - tools, paste the whole of gtm/coaching_fab_tools.html. Leave “Support document.write” off; Advanced Settings > Tag firing options: Once per page.
  2. Trigger: Triggers > New > Page View, “Some Page Views”, Page Hostname equals programs.clearerthinking.org. (Page Hostname is already an enabled built-in variable in this container.)
  3. Optional GA4 event: Custom Event trigger coaching_fab_click → GA4 Event tag on G-58RPQ2D860, event name coaching_fab_click, parameters link_url and link_text from the existing data-layer variables. Skip it if filtering cta_click by link_url is enough.
  4. Preview (Tag Assistant) on a tool page: the tag fires once and the button shows; on www.clearerthinking.org: the tag must not fire; on personality-test.html: nothing before the CTA, button after it. Also open the three-dot run menu on a phone-sized window to see the button over the dimmed overlay.
  5. Publish with a version note. Rollback: pause the tag, or republish the previous container version.

6. Decisions still yours

  • Pages to exclude. HIDE_ON in the snippet is empty, so the button shows on every programs.* page, including the dashboard, Paths, the members-only content and the career-workshop recording. Add path prefixes there if any of those should stay clean.
  • Link parameters. Decided 2026-10-21: the link uses the Wix utm set (utm_source=tools&utm_medium=banner&utm_campaign=tools_floating_button) instead of the tested ?src=tools_fab; the trade-off is explained in section 3.
  • Always on, or only after results? The tools already push started_program, reached_email_ask, made_it_passed_email_ask and finished_exercise to the data layer, so the same tag could instead fire on one of those if a mid-test button proves distracting.
  • Ad-blocker gap. Comparing GA4 page views with GuidedTrack run counts for one tool over a week would size it; that number decides whether option B is worth the team’s time.
